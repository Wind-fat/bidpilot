# 引用定位精度（41 页真实语料实测）

这份文档回答两件事：**引用能不能按页码 + 页内偏移精确找回**，以及**章节标签会不会因为
「同一页起两章」而落到上一章上**。所有数字都来自 `evals/datasets/tender_jiangsu.pdf`
（41 页，真实招标文件）跑出来的 `out/jiangsu_extract.json`，命令见 §5，可原样复现。

## 1. 结论

| 指标 | 修正前（按页首归属） | 修正后（按 quote 落点归属） |
|---|---|---|
| 章级标签与引用落点一致 | 149 / 170 | **170 / 170** |
| 同页跟章导致「标签偏一章」 | **21 条** | 0 条 |
| 每条带页内字符区间（可机械回查） | 0 / 170（只有页码） | **170 / 170** |
| 可回查（page + quote_span + slice_text 逐字命中） | 不适用 | **可回查 170/170** |

21 条改归的分布：评分项 11 条、废标条款 3 条、技术要求 7 条；
集中在 3 个「同页起两章」的边界页（p4 两条、p11 十二条、p13 七条）。
一句话：**这 21 条原来被算成上一章的，修正后落到它们真正的章里**，而且不是靠放松校验换来的
（见 §4，校验只加了不减）。

## 2. 机制

`Section` 的边界早就是 `(page_start, char_start, page_end, char_end)`，
但**回填标签时用的是 `section_at(page, 0)`**：整页都算页首那一章。于是只要下一页的章标题
起在本页中间（真实招标文件里几乎必然如此——章标题前面还有页眉/页码），本页章标题之后的
所有条目都会被记到上一章名下。

改动有三处：

1. **条目多一个证据区间** `quote_span = (页, 页内起, 页内止)`（`schemas._Located`）。
   它由 `extract._check_quote` 定位 quote 后写入，**模型自报的同名字段一律覆盖**——
   模型给不出可核验的偏移，采信它等于把校验交给被校验方。
2. **标签按落点回填**：`section = section_at(quote_span[0], quote_span[1]).title`
   （`extract._label_chapter`）。评分项 / 废标条款 / 技术要求三者统一。
3. **跨页条目的证据页不再被抹掉**：旧代码在「quote 只在结束页找到」时把 `page_end` 塌成
   `page`，等于宣称证据在起始页；现在 `page`/`page_end` 保持条目声称的跨度，
   证据落在哪页由 `quote_span[0]` 说清楚。

同时 `pipeline` 里按章聚合生成计划也改成 `chapter_of(page, offset)`：章节标签偏一章，
生成计划的归章就跟着偏，这不是只在 JSON 里改个字段的事。

## 4. 校验只加严，没有放宽

这次没有放宽任何一条旧校验，新增的都是更严的：

| 位置 | 更严在哪 |
|---|---|
| `schemas._Located.check_span_in_pages` | `quote_span` 的证据页必须落在条目自己的 `page..page_end` 内，否则 `needs_review` |
| `extract._check_quote` | 新增「page 超出文档页数」「定位区间越出页长」两道闸，返回区间给上层 |
| `extract._stamp` | 模型自报的 `quote`/偏移一律被定位结果覆盖（不再存在「模型说在哪就在哪」的路径） |
| `extract.relocate` | 分阶段跑加载旧 JSON 时逐条重定位，**定位不到就标 `needs_review` 并列明细**，不猜偏移、不删条目 |
| `extract._validate_tech` | 跨页条目不再把 `page_end` 塌成 `page`（旧行为等于把证据页写错成起始页） |
| `citations.check_item` | 独立复核：`page`/`quote_span`/`slice_text`/子串/标签五项，任何一项不符都算不可回查 |
| `pipeline` | 按章聚合改用 `chapter_of(page, offset)`，标签偏一章会连带生成计划归错章 |

已有的「quote 必须是该页原文逐字子串」「块内页范围」「同页跨章区间」等校验原样保留。

```bash

    --no-generate --no-db \
    --extract-json out/jiangsu_extract.json --extract-out out/jiangsu_extract.json

    --pdf evals/datasets/tender_jiangsu.pdf --extract-json out/jiangsu_extract.json
```

## 6. 已知边界

- **没有章节标题的文件**（`_fallback_sections` 按关键词聚合的伪章节）仍然只有页级边界，
  `char_start=0` / `char_end=页长`。这类文档没有可靠的页内章节边界可依据，页内跟章问题无从谈起：
  标签精度退化到页，但不会因为这次改动而变松——`quote_span` 照样写入，回查照样做。
- `quote_span` 是**派生**数据：不是模型产出的证据，而是「按 page + quote 在原文里定位」的结果。
  它能证明「这句话确实在这一页这个位置」，不能证明「模型理解的语义正确」。
- 改归明细里的字符偏移会随 documind 解析器变化而变（PDF 抽文一变，页文本就变）；
  数字以当前 `b871620` + 当前 documind 版本为准。
