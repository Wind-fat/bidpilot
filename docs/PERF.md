# BidPilot 性能实测（200 页）

验收尺子里有一条「200 页招标文件 ≤ 20 分钟」。这份文档记录**实测数字、命令与口径**，
避免把"含 LLM 生成"和"不含 LLM"的两种耗时混在一起比较。

## 1. 结论

| 口径 | 200 页实测 | 验收尺子 | 说明 |
|---|---|---|---|
| **解析 + 切章**（`load_tender`） | **12.4 s**（5 次最好） / 12.4–15.5 s（5 次区间） | — | pypdf 抽文 + 分页分段 + 章节切分 + 废标扫描 |
| 抽取 JSON 读取 + 能力矩阵 + 计划 + 导出（`generate=False`） | 0.1–0.2 s | — | 复用已落盘的抽取结果，**0 次 LLM 调用** |
| **单次完整跑（不含 LLM 生成）** | **12.6 s**（最好） / 15.6 s（最差） | 1200 s | 占预算 **1.1%** |
| 生成阶段（LLM） | **未计入** | — | 本次用 `--no-generate` 跳过；见 §4 口径 |

参考基线（同一脚本、同一台机器，41 页真实语料）：解析+切章 0.94–2.9 s，单次全流程 1.04–2.98 s。
即 200 页 ≈ 41 页的 5 倍页数，解析耗时也在 4–13 倍区间内线性增长（波动见 §5）。

**一句话结论**：不含 LLM 的部分，200 页在 **13 秒级**完成，离 20 分钟预算差两个数量级；
真正吃掉 20 分钟预算的是 LLM 生成阶段，而它不在本文件的测量范围里（也没有可用网关可测）。

## 3. 命令

```bash
# 200 页（把 41 页真实语料循环拼接到 200 页，pypdf 本地拼接，不联网）
./.venv/Scripts/python.exe scripts/bench_200p.py --repeat 5

# 41 页基线（同一脚本、同一口径）
./.venv/Scripts/python.exe scripts/bench_200p.py --pages 41 --out-dir out/perf41 --repeat 3
```

脚本做的事：

1. `out/perf/tender_200p.pdf`：`reader.pages[i % 41]`（i = 0..199）→ 200 页 / 697,958 bytes；
2. 计时 A：`load_tender(pdf)` —— **解析 + 切章**；
3. 计时 B：`run_pipeline(pdf, generate=False, save_db=False, extract_json=out/jiangsu_extract.json)`
   —— 抽取结果读盘 + 能力矩阵 + 生成计划 + 导出 docx，**0 次 LLM 调用**；
4. 明细落 `out/perf/bench_200p.json`（每次运行的 parse/切章/废标扫描/整段耗时、段落数、章节数）。

## 4. 口径声明（重要）

- **不含 LLM**：`--no-generate` 之外，抽取也走 `--extract-json`（复用上一轮已落盘的结果），
  所以 0 次模型调用、0 token。**12.6 s 是"程序侧"耗时，不是端到端交付耗时。**
- **生成阶段**才是 20 分钟预算的主要消耗方：41 页语料 ≈ 14 个抽取块 + N 个生成批次，
  每块一次或多次模型调用；200 页语料按块数线性放大。这部分本轮**没有实测数字**，
  因为没有可用网关（默认网关地址在本机不可用），也不允许在验收里伪造。
- `run_pipeline` 内部会**再解析一次**文档，因此"解析 + 其余"两段相加 = 一次完整跑；
  报告里没有把两次解析相加当成分项成本。
- 拼接语料是**同一份文档循环 5 次**：段落/页数线性增长（1251 段 / 200 页），
  但章标题重复，`_dedupe_headings` 只保留首次出现，所以切章在本次实测里只覆盖 5 个章节
  （41 页基线也是 5 个）——**切章成本被低估，解析成本是真实的**。切章本身实测 0.002–0.011 s，
  即使章节数放大 25 倍也在 0.3 s 量级，不影响结论。

## 5. 5 次原始数据（200 页）

| 次 | 解析+切章 | 其中切章 | 其中废标扫描 | 抽取+矩阵+导出 | 单次全流程 |
|---|---|---|---|---|---|
| 1 | 12.38 s | 0.003 s | 0.004 s | 0.20 s | 12.58 s |
| 2 | 15.47 s | 0.004 s | 0.004 s | 0.10 s | 15.57 s |
| 3 | 14.83 s | 0.003 s | 0.004 s | 0.10 s | 14.93 s |
| 4 | 14.98 s | 0.003 s | 0.004 s | 0.10 s | 15.08 s |
| 5 | 14.79 s | 0.003 s | 0.004 s | 0.20 s | 14.99 s |

段落 1251 / 章节 5 / 废标命中 40 / 退出码 3（示例能力库） / LLM 调用 0（每次运行一致）。

波动来源：首轮磁盘/杀毒冷启动（同一份 PDF 第一次读 12 s，之后 15 s 上下），
以及 Windows 上 pypdf 纯 Python 解析的单线程特性。**取最好成绩画像、报区间**，
不拿单次最优当承诺值。

## 6. 复现注意

- `out/perf/` 里的 docx 是 `--no-generate` 的**阶段产物**：首行带
  「本文件只有抽取与能力矩阵结果……不能作为投标文件使用」横幅，退出码 3 表示能力库是示例数据；
  它不是交付物。
- 换机器/换 Python 版本后数字会变（pypdf 是纯 Python，单核性能直接决定解析时间）；
  重新跑上面的命令即可刷新，不需要改代码。
